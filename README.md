# 自動部屋割り君

柏島ヴィレッジ向け、ねっぱんCSVから部屋割り表を自動生成するWebアプリです。
複数端末（Mac・iPadなど）から同じURLにアクセスして、割り当てを見る・編集する・Excelを書き出すことができます。編集内容はその場でサーバーに自動保存されます。

## できること

- ねっぱんの予約CSV（Shift_JIS）をアップロード
- 日付を選んで「部屋割りを自動生成」（仕様書のルールに基づく叩き台）
- 生成結果をブラウザ上で直接編集（名前・サイト・金額・大人/子供/幼児人数・メモの書き換え、空室化）→ 変更は即時保存
- 大人/子供/幼児人数は各部屋の定員までの範囲で編集可能（401は大人4・子供2・幼児2、601は大人6・子供3・幼児3、通常個室は大人1・子供1・幼児1が上限。`logic/roomMaster.js` の`ROOM_CAPACITY`で調整可能）
- 「要確認」がついた箇所はハイライト表示（理由付き）
- 既存Excelと同じレイアウトで .xlsx をダウンロード（大人/子供/幼児人数を列で個別表示、メモをコメントで表示）
- 連泊客は前日の割当を自動的に引き継ぎ（部屋の移動が起きないようにする）
- CSVアップロード時にキャンセル行を検出し、既に部屋が割り当てられていれば自動で空室化
- CSVの「その他明細」列（AN列）を各部屋のメモ欄にそのまま反映
- 108号室の下に「RV」という完全手動入力の枠を追加（CSVからは自動割当されません）。大人+子供+幼児の合計で定員20名まで入力可能（超過分は幼児→子供→大人の順で自動的に削られます）
- 「3日間ビュー（印刷用）」ボタンで、選択した日から3日分をA4縦1ページずつ縦に並べた閲覧・印刷専用ページを表示（RV枠も含む）。編集はできません。「印刷する」ボタンでブラウザの印刷機能を呼び出します
- **画面はコンパクトなタイル表示**：部屋番号・お名前・人数だけを表示する小さいタイルが1画面に収まるよう並び、タップすると詳細編集モーダルが開きます（スクロールを最小限にするための表示切り替えです）
- **タイルのドラッグ&ドロップ入れ替え**：2つの部屋タイルをドラッグ&ドロップすると、予約者・人数・食事・メモなど中身をまるごと入れ替えられます
- **固定（ロック）ボタン**：詳細モーダル内の「未固定→タップで固定」ボタンで、その部屋をCSV再取込時の自動上書き対象から外せます。フロア見出しの「全固定/全解除」でフロア単位の一括切り替えも可能です。**通常の編集（名前・人数・食事・メモの変更）だけでは自動的に固定されません**。上書きされたくない変更をした後は、必ず固定ボタンを押してください
- **食事・オプションの個数カウンター**：詳細モーダルに「素泊／夕食メイン／朝食／オプション」のカテゴリ別に個数を+/-で入力できるカウンターを用意（`logic/mealItems.js`で項目を管理）。CSV自動生成時はプラン名から人数分を初期値としてセットしますが、後から自由に調整できます
- **画面下部のライブ食事集計表**：選択中の日の全部屋分の食事・オプション数量を一覧表示（部屋ごとの列・メニューごとの行・右端に合計）。Excelの食事集計表と同じ考え方で、常に最新の入力内容を反映します

## この実装にあたって決めたこと（要確認いただきたい点）

仕様書と実際のExcel実例を照らし合わせて、以下のように解釈・補完しました。運用しながら違っていたら教えてください。

1. **部屋の物理レイアウト**：1階は101-104・105-108の間に納戸があり、104と105は隣接していません。2階は納戸が無く201〜209が連続しています。納戸の直上が205です（実例のTORU WAKANA/まつだかれん等の部屋番号対応から確認）。
2. **食事集計表の列**：仕様書のプラン名は固定リストではなく、アップロードしたCSVに実際に出てきたプラン名からキーワードで自動分類し、列を都度生成する方式にしました（表記ゆれ・新プラン追加のたびにマスタ更新しなくて済むようにするため）。未知のキーワードは「その他:○○」として集計されます。`logic/classify.js` のPLAN_KEYWORDSにキーワードを追記すれば分類精度を上げられます。
3. **2人区画・4人区画の人数判定**：CSVの「室数」列は常に1になっていたため、「大人人数計＋子供人数計」を必要部屋数として、1階(切り上げ半分)＋直上の2階(残り半分)に割り振ります。
4. **追加の要確認条件**：同じ宿泊者名で同日に複数予約がある場合（個室＋ドミトリー等の組み合わせ）も「要確認」として表示するようにしました（実例の「岡山栄次様」のケースに対応）。
5. **連泊客**：前日以前にチェックインし当日もチェックアウトしていない予約は「連泊中」として扱い、アプリが記憶している前回の部屋番号をそのまま引き継ぎます。もしアプリ導入前から泊まっている連泊客がいる場合、その方の初回分はアプリに記録が無いため「要確認：部屋番号未登録」と表示されます。その日だけ手動で部屋を入力すれば、翌日以降は自動的に引き継がれます。
6. **3人区画**：「【ドミトリー】3人区画」を独立カテゴリとして追加し、予約が入った場合は2階の隣接2室＋その直下の1階1室、という固定パターンで割り当てます（ご指示の通り）。まだ実績データが無いため、実際に予約が入り始めたら割り振り結果をご確認ください。
7. **キャンセルの空室化**：CSVアップロード時に「予約区分＝キャンセル」の行を検出し、その予約IDが既にどこかの日付で部屋に割り当てられていれば、その部屋を自動的に空室に戻します（手動編集で入れた内容も含めて上書きされます）。アップロード後の画面に「空室化した部屋」の一覧がポップアップで表示されます。
8. **メモ欄**：CSVの「その他明細」列（AN列）の内容をそのまま各部屋のメモ欄に反映します。画面上で追記・修正も可能です。Excel出力では「メモ」列に30文字までの要約＋セルコメントで全文を表示します。
9. **固定（ロック）の考え方**：「編集する＝固定される」ではありません。名前・人数・食事・メモを変更しただけでは固定されず、次にCSVを取り込んで「生成/更新」を押すと上書きされる可能性があります。上書きされたくない部屋は、詳細モーダルの固定ボタン（またはフロア見出しの「全固定」）を明示的に押してください。固定した部屋は空室であっても自動割当の対象から外れます。

## デプロイ方法（無料・コマンド操作なしでOK）

データベースに **Turso**（無料・SQLite互換）、アプリのホスティングに **Render**（無料）を使います。どちらも無料枠で運用できます。GitHubにコードを置く必要があるので、GitHubアカウントも使います。

### 手順1: GitHubにコードを置く

1. https://github.com にログイン（アカウントが無ければ新規登録）。
2. 右上の「+」→「New repository」。リポジトリ名は好きな名前（例: `heyawari-kun`）。Public/Privateどちらでも構いません。「Create repository」。
3. 作成後の画面で「uploading an existing file」というリンクをクリック。
4. このフォルダの中身（`server.js`, `db.js`, `logic/`, `public/`, `package.json`, `render.yaml` など。**`node_modules`フォルダと`data`フォルダは含めない**）をまとめてドラッグ&ドロップしてアップロードし、「Commit changes」。

### 手順2: Tursoで無料データベースを作る

1. https://turso.tech にアクセスし、「Get Started」等からアカウント登録（GitHubアカウントでログイン可）。
2. ダッシュボードで「Create Database」。名前は任意（例: `heyawari-kun`）。リージョンは近い場所（Tokyo等）を選択。
3. 作成したデータベースの画面で「Connect」または「Tokens」から
   - **Database URL**（`libsql://xxxx.turso.io` の形式）
   - **Auth Token**（発行ボタンから新規作成）
   の2つをコピーして、メモしておく（この2つを手順3でRenderに設定します）。

### 手順3: Renderにデプロイする

1. https://render.com にアクセスし、GitHubアカウントでログイン。
2. 「New +」→「Web Service」。手順1で作ったリポジトリを選択して連携。
3. 設定画面で以下を確認・入力:
   - Runtime: Node
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Instance Type: Free
4. 「Environment Variables」で以下の2つを追加:
   - `TURSO_DATABASE_URL` … 手順2でコピーしたURL
   - `TURSO_AUTH_TOKEN` … 手順2でコピーしたトークン
5. 「Create Web Service」。数分でビルドが終わると、`https://（サービス名）.onrender.com` というURLが発行されます。これがアプリのURLです。ブックマークしておけばMac・iPadどちらからも同じ画面・同じデータにアクセスできます。

※ Render無料プランは15分アクセスが無いとスリープします。次回アクセス時に数十秒立ち上がりに時間がかかることがありますが、データはTurso側に保存されているため消えません。

### 動作確認

アプリのURLを開き、CSVをアップロード→日付を選んで「この日の部屋割りを生成/更新」を押して、部屋割りが表示されることを確認してください。

## ローカルで試す場合（任意）

```
npm install
npm start
```
`http://localhost:3000` を開く。この場合はTursoの環境変数を設定しなければ、`data/db.sqlite` にローカル保存されます（Renderにデプロイする場合はこのファイルは使われず、必ずTursoが使われます）。

## 運用上の注意（仕様書より）

- 出力はあくまで「叩き台」です。特にリピーター対応・家族構成など、CSVに出てこない情報は反映されないため、最終確認は必ず人が行ってください。
- 部屋タイプ名称がねっぱん側で変更・追加された場合は `logic/classify.js` の `ROOM_TYPE_CATEGORY` を更新してください（未知の名称は自動的に「要確認」として表示されるので実害はありません）。
- キャンセル・当日の電話予約等はCSVに反映されないため、本アプリでは扱いません（既存の運用通り、手動で対応してください）。
